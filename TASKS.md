- [x] **Fixed cross-account session bleed: Admin and staff logging into the app on the same machine shared one session** (2026-08-17) - user reported that as Shop Manager, clicking "Show all" on Expense Claims unexpectedly landed them in the Admin dashboard. Root cause: `AuthContext.tsx`/`api.ts` stored the login session in `localStorage`, which is shared across every tab of the same browser with no per-tab isolation - so a second staff member logging in on the same machine (new tab or reused tab) silently overwrote the first person's session; the whole browser was authenticated as whoever logged in most recently, not per-tab. Fixed by moving all three session keys (`accountgo-token`/`accountgo-user`/`accountgo-tenant-id`) to `sessionStorage`, which is genuinely per-tab - trade-off (a session no longer survives closing the tab) is the right default for a shared shop computer where staff log in per shift. Live-verified via Playwright reproducing the exact scenario: two tabs, one browser context, Admin then Shop Manager login - both stayed correctly isolated to their own account after reload. See STATUS.md.
